# Project Schedule Lab 0.2.0

단일 사용자·로컬 실행용 Python/Tkinter 프로젝트 일정·이력관리 도구입니다. 엑셀로 입력을 교환하고 SQLite에 프로젝트·작업·관계·달력·승인 기준 일정·예측·실적·변경 및 Import 이력을 저장합니다. 프로젝트 업종·지역에 종속되는 규칙은 없습니다.

## 설치와 실행

Python 3.11 이상(Tcl/Tk 포함)이 필요합니다. 권장·검증 환경은 Python 3.12입니다. EXE가 아닌 **전체 Python 소스와 실행 스크립트 배포본**입니다.

- Windows: 압축을 쓰기 가능한 폴더에 풀고 `install.bat`, 설치 성공 후 `start.bat` 실행. 기존 파일을 덮어 설치하지 말고 별도 폴더를 권장합니다.
- Linux/macOS: Tk가 있는 Python에서 `./install.sh`, 그래픽 데스크톱에서 `./start.sh` 실행. Linux에서 Tk가 없으면 배포판의 Python/Tk 패키지가 필요합니다.
- 직접 실행: `python -m pip install -r requirements.txt`, `python app.py`.
- 네트워크는 의존성 설치에만 필요합니다. 외부 API·계정·서버·비밀키는 필요 없습니다.
- 의존성: `numpy>=1.24,<3`, `openpyxl>=3.1,<4` 및 간접 의존성 et-xmlfile. 검증한 정확한 버전은 `requirements-validated.txt`입니다(해당 파일은 Python 3.12 환경용).
- GUI가 없는 클라우드에서는 Xvfb 등 X 디스플레이로 자동 GUI 검증할 수 있습니다. 이 앱은 웹 서비스가 아니며 가상 디스플레이만으로 사용자 화면이 제공되지는 않습니다.

작업 폴더는 이 README와 `app.py`가 있는 폴더입니다. 저장소의 기존 디렉터리 이름(v0.1.0)은 호환을 위해 유지했으며 프로그램·엔진 버전은 0.2.0입니다.

## 빠른 사용과 화면

1. **프로젝트 메뉴**에서 새 프로젝트를 만들거나 저장 프로젝트를 엽니다. 서로 다른 프로젝트는 내부 UID로 격리됩니다. Ctrl+S로 저장할 수 있고 화면 편집도 즉시 저장합니다.
2. **일정 · 데이터 → 모듈 추가 · 적용**에서 모듈을 관리합니다. 작업 편집에서 업무를 입력하거나 **엑셀 가져오기**를 선택합니다.
3. **엑셀 사전 검토**에서 신규·수정·동일·누락·충돌과 전후값·셀 진단을 확인합니다. 변경 행을 더블클릭해 선택/해제하고 사유를 입력한 후 적용합니다. 경고 및 선택한 충돌 덮어쓰기는 확인란으로 명시적으로 확인해야 합니다.
4. **관계 유형 · 시차**에서 FS/SS/FF, 시차, 단위, 달력, 근거·필요 산출물을 편집합니다. 새 행/선택 행 수정 후 전체 저장합니다.
5. **달력 · 추가 근무일**에서 달력별 요일·휴일·추가 근무일을 편집합니다. 작업 상세에서 기간단위와 달력 ID를 선택합니다.
6. **설정**에서 착수일·기준일·목표일, 작업 상세에서 실적·잔여 O/M/P·재개일·고정 날짜를 입력합니다.
7. **M 기준 재계산**으로 예측·임계 작업·총 여유·목표일 차이를 확인합니다. 기존 **시뮬레이션 실행**은 같은 규칙으로 몬테카를로를 수행하고 로드맵·분포에 연결합니다. 확률 결과 자체에는 CPM 여유가 없으며 여유는 M 계산에서 확인합니다.
8. **기준선 저장**은 현재 M 계산 결과를 이름/승인 근거와 함께 새 기준 일정 버전으로 저장합니다. **기준 일정 버전 조회**로 과거 날짜를 읽습니다.

창의 확률 메트릭은 M 계산에서는 같은 날짜가 반복 표시됩니다(확정 1회). `예측 · 임계 · 오류` 탭에 계산 종류·엔진·입력 버전·기준일·반복·Seed와 경고가 표시됩니다. 결과의 음수 목표일 차이는 지연을 뜻합니다.

## Import 안전 정책

- **Activity ID는 프로젝트 내 고유**, 내부 UID는 불변입니다. 업무명·WBS·행 순서로 자동 병합하지 않습니다. 프로젝트 복제는 프로젝트 UID·작업 UID·Activity ID를 새로 만들고 모든 관계를 매핑합니다. 승인·변경 이력은 원 프로젝트에 보존하며 복제본에 이전 승인으로 복사하지 않습니다.
- 필수 헤더가 있는 외부 파일에서 ID가 비어 있으면 **신규 프로젝트 등록**에서만 새 ID를 만들고 경고합니다. 기존 프로젝트로 병합하려면 사용자에게 ID 지정을 요구합니다. 임의 양식의 자동 열 매핑/유사 이름 병합은 지원하지 않습니다.
- **빈 셀은 기존 값 보존**, 문자 `__CLEAR__`는 명시적 삭제입니다. 필수값을 지우면 검증 오류가 됩니다. 휴일/추가근무일 목록 전체를 지우려면 해당 시트 날짜 셀에 `__CLEAR__` 한 행을 두세요. 빈 시트는 보존입니다. 일반적으로 값을 바꿀 때는 새 값을 입력합니다.
- **누락 작업을 삭제하지 않습니다.** 모듈·달력 전체 설정과 관계 네트워크는 비교 미리보기의 묶음 변경 항목입니다. 관계 시트에서 행을 지운 경우 관계 목록의 변경 전후를 검토하고 그 항목을 선택해야 삭제가 반영됩니다. 작업 삭제의 대체 정책은 제외 상태이며 원 데이터·관계는 보존합니다.
- **관계 시트 우선**: 기존 `선행 ID` 열과 불일치하면 경고합니다. 관계 시트가 없으면 `선행 ID`를 FS·달력일 시차 0으로 변환합니다. 빈 선행 ID는 기존 관계 보존, `__CLEAR__`는 해당 후행의 관계 해제입니다.
- Export에 스키마 `PSL-2`, 프로젝트 UID, 데이터 버전을 기록합니다. 과거 Export와 현재 입력을 3방향 비교합니다. 엑셀에서 안 바꾼 필드는 현재 앱의 수정을 보존합니다. 양쪽이 같은 필드를 다르게 수정하면 충돌로 표시하고 기본 미선택합니다. 기준 버전 없는 외부 파일의 기존 값 변경도 충돌로 표시합니다. 관계·달력·모듈 묶음 충돌은 전체 전후를 검토해야 합니다.
- 미리보기 이후 DB 버전이 바뀌면 적용을 거부하고 재비교를 요구합니다. 오류는 적용 차단, 경고는 확인 후 적용입니다. 신규 행을 제외하고 그 행을 참조하는 관계만 선택한 경우도 적용 직전에 재검증합니다.
- Import 전 SQLite 백업을 생성하고 입력·필드 이력·Import 성공 기록을 **단일 트랜잭션**으로 반영합니다. 실패하면 전체 롤백하고 실패 기록만 별도로 남깁니다. 검토 기록도 저장합니다.
- 변경 없는 Export→Import 및 저장은 입력 데이터 버전·변경 이력·입력 이벤트를 늘리지 않습니다. Import 실행 기록과 복원 지점은 별도로 남습니다.

## 엑셀 형식과 보존 범위

`examples/standard_template.xlsx`는 빈 표준 템플릿, `validation_small.xlsx`는 FS·SS·FF 검증 예제, `calendar_example.xlsx`는 혼합 달력 예제입니다. 표준 템플릿 날짜와 휴일은 예시이며 실제 프로젝트에 맞춰 직접 변경하세요.

표준 시트: `프로젝트`, `모듈`, `작업목록`, `관계`, `휴일`, `추가근무일`, `달력`, `메타데이터`, `사용안내`. 선택적으로 `기준일정버전`(조회용), `분석요약`, `작업결과`를 출력합니다. 기존 필수 열은 유지하고 WBS·달력 ID·고정 날짜·재개일·진척률·UID를 뒤에 추가했습니다. 기존 PSL-0.1과 common Rev1 입력도 읽습니다.

기본 달력의 휴일·추가근무일은 각각 해당 시트가 기준입니다. `달력` 시트의 default 행은 주간 근무 요일을 정하며 기본 날짜 목록은 두 시트에 맞춰 정규화합니다. 사용자 지정 달력은 `달력` 시트에 weekmask/holidays/workdays로 관리합니다.

표준 Export는 **현재 구조화된 일정 입력과 선택한 계산 결과**를 출력합니다. 원본의 임의 시트·그림·서식·주간간트·리스크/문서대장 및 전체 변경 DB를 복제하지 않습니다. 조회용 기준 일정 버전 시트는 Import로 승인 버전을 만들거나 덮어쓰지 않습니다. 전체 이력/승인은 DB 백업으로 이동합니다. 화면에서 읽은 원본과 같은 경로로 Export하지 못하도록 차단합니다. 별도 이름으로 저장하세요. 원본 common_Rev1.xlsx는 변경하지 않았습니다.

## 계산 정의

- 날짜는 일 단위, 경과일 방식입니다. 10/1 착수·1달력일 작업은 10/2 완료, 0일 마일스톤은 같은 날입니다. FS+0은 선행 완료일에 후행 착수가 가능합니다.
- 근무일 양수 기간은 시작이 비근무일이면 다음 근무일로 보정한 후 일수를 더합니다. 금요일 1근무일은 월요일 완료입니다. 0일은 보정하지 않습니다. 추가 근무일이 휴일/주말보다 우선하며 자동 공휴일은 없습니다. 달력의 지원 날짜는 1900-01-01~2199-12-31입니다.
- 관계별 시차의 단위와 달력 ID를 사용합니다(기본: 달력일/default). 근무일 양수 시차도 비근무일 기준점을 앞으로 보정한 후 일수를 더합니다. 0은 보정하지 않습니다. 음수·소수 시차·SF는 검증 오류입니다.
- FS: 후행 시작 ≥ 선행 완료+시차. SS: 후행 시작 ≥ 선행 시작+시차. FF: 후행 완료 ≥ 선행 완료+시차. FF는 후행 기간/달력을 역으로 계산해 필요한 시작 하한을 구합니다. 복수 조건을 모두 만족시키며 순환 경로·자기 참조·없는/다른 프로젝트 ID를 차단합니다.
- 계획(미착수)은 착수일·기준일·가장 이른 착수 가능일·관계를 반영합니다. 보류는 재개 가능일이 없으면 미확정으로 계산 차단합니다. 해제 조건 메모만으로 재개일을 자동 추정하지 않습니다.
- **기준일은 당일 시작 시점의 실적**입니다. 진행 중 실제 시작은 보존하고 당일부터 잔여 O/M/P를 계산합니다. 진척률에서 잔여기간을 만들지 않습니다. 미완료 FS 선행이 있으면 잔여 작업을 선행 완료 뒤로 지연시키며 FF도 예측 완료 하한에 적용합니다. 이미 발생한 착수에 대한 SS/FS 위반은 경고합니다.
- 완료는 실제 시작/완료를 보존합니다. 실적 관계 위반은 경고하며 실적을 바꾸지 않습니다. 실제 날짜와 상태·진척률의 모순은 검증 오류입니다. 진행·완료 작업의 고정 날짜가 실제/예측과 충돌하면 계산을 차단합니다.
- 고정 시작·완료는 반드시 일치해야 하는 제약입니다. 관계·달력·기간과 충돌하면 실패합니다. **목표일**은 별도 관리 기준이며 일정이나 기간을 잘라 맞추지 않습니다.
- 제외 작업에 연결된 관계가 남아 있으면 계산을 차단합니다. 영향 목록에 원 관계·근거·산출물을 표시하고 원복하거나 명시적으로 관계를 수정하도록 합니다. 자동 재연결을 하지 않습니다. 독립된 제외 작업은 프로젝트 완료일/임계 작업에서 제외합니다.
- M 기준 순방향·역방향 계산으로 예측·총 여유·임계 작업을 산출합니다. 복수 종료 작업 중 가장 늦은 완료가 프로젝트 완료일입니다. **총 여유는 달력일 차이**로 표시하며 목표일까지 차이와 독립적입니다. 실제 시작이 고정된 진행/완료는 전체 작업 여유를 정의하지 않습니다. 진행 작업의 남은 구간은 FS/FF 역방향 경계에 반영하고 완료된 실적을 향한 과거 관계는 미래 여유를 제한하지 않습니다. 고정 날짜 작업의 이동 여유는 0입니다.
- 결정론적 계산은 M 올림, 몬테카를로는 독립 삼각분포 표본 올림이며 **같은 `_run` 계산 규칙**을 사용합니다. O=M=P, 0일을 지원합니다. 매 반복마다 제약을 만족해야 하며 일부라도 불가능하면 전체 분석을 실패로 처리합니다. 최대 2,000개 작업, 20,000회 반복입니다.
- 계산 결과는 프로젝트 UID·데이터 버전·기준일·반복·Seed·엔진 버전에 연결합니다. 저장 결과는 작업별 중앙 날짜·요약·경고 및 M 여유이며 모든 몬테카를로 배열은 저장하지 않습니다. 재실행 후 결과 차트는 재계산하세요. 동일 환경·버전·입력·Seed에서 재현합니다.

## 저장·마이그레이션·백업·복원

- Windows: `%LOCALAPPDATA%\ProjectScheduleLab\history.sqlite3`.
- POSIX 실행 스크립트: `${XDG_DATA_HOME:-$HOME/.local/share}/ProjectScheduleLab/history.sqlite3`. `LOCALAPPDATA`가 있으면 해당 경로 우선. 직접 실행은 구버전과 같은 홈 디렉터리를 기본으로 합니다. 기존 POSIX 사용자는 **기존 DB가 있는 부모 경로로 LOCALAPPDATA를 지정**해 같은 DB를 여세요. DB 파일을 여기저기 옮겨 이력이 나뉘지 않도록 확인하세요.
- DB schema version 2 (`PRAGMA user_version`). 프로젝트·버전·작업·관계·모듈·달력·필드 이력·기준 일정·예측·Import 표를 분리했습니다. 원천 수정과 재계산은 별도로 저장합니다.
- v1 events-only DB를 처음 열면 SQLite backup API로 `.pre-v2-시각.sqlite3`를 먼저 만들고 하나의 트랜잭션으로 이전합니다. 기존 events 원문을 그대로 보존하며 프로젝트별 마지막 스냅샷을 복구합니다. 실패하면 스키마·입력 모두 롤백합니다. 더 최신 DB 버전은 열지 않습니다.
- **이전 전 수동 사본도 권장합니다.** 모든 구버전/신버전 프로그램을 종료하고 DB를 복사한 다음 새 프로그램을 실행하세요. 기존 DB를 삭제하거나 초기화할 필요가 없습니다.
- v1에는 내부 프로젝트 UID가 없으므로 이전 시 **공개 PJ_ID 기준**으로 그룹화합니다. 같은 PJ_ID를 다른 프로젝트에 재사용했던 경우 자동 판별할 수 없습니다. 원 이벤트는 모두 보존되므로 별도 사본에서 이력을 확인해 수동 분리해야 합니다. 업무명 유사도로 임의 병합하지 않습니다.
- v1의 ‘기준선’은 **입력 스냅샷**으로 표시하여 보존합니다. 계산된 승인 날짜 버전으로 간주하지 않습니다. 검토 후 새 M 계산 기준 일정을 별도로 승인하세요. v1 기준 시작/완료 열은 참고 입력으로 유지합니다.
- Import 전 `.pre-import-*`, DB 복원 전 `.pre-restore-*` 복원 지점을 생성합니다. 백업 파일은 자동 삭제하지 않습니다. 필요 시 사용자가 보관 정책을 정하세요.
- **프로젝트 → DB 백업**은 열린 DB에서 일관된 전체 백업을 생성합니다. 이미 있는 파일을 덮어쓰지 않습니다. **DB 복원**은 파일 무결성/스키마/참조를 검사하고 현재 DB 백업을 만든 뒤 연결을 닫고 파일을 원자적으로 교체하고 다시 엽니다. 복원은 모든 프로젝트를 해당 시점으로 되돌립니다. 다른 앱 인스턴스는 닫으세요. v1 백업은 별도 폴더에서 먼저 이전한 뒤 복원합니다.
- 이력의 **입력 복원**은 선택한 프로젝트 입력을 새 버전으로 저장하며 승인 기준 일정 목록은 유지합니다. DB 전체 복원과 구별하세요.
- 공유폴더 동시 편집·다중 사용자 권한/승인 서버는 지원하지 않습니다. 사용자 이름은 로컬 OS 계정명이며 인증된 전자서명이 아닙니다.

## 검증 및 검수

자동 검증: `python -m unittest test_core test_v2 -v`. GUI: 유효한 DISPLAY에서 `python -m unittest test_gui -v` (없으면 GUI 3개는 명시적으로 skip). `python generate_examples.py`는 예제·원본 검토 보고서를 다시 만듭니다. 실행 증거는 `reports/validation.md`, `reports/test_results.txt`를 참고하세요.

짧은 검수 절차:

1. 새 프로젝트 대신 `examples/validation_small.xlsx`를 신규 Import합니다. 오류 없음 확인 후 적용하고 M 재계산합니다. A=10/1~10/5, B=10/2~10/4, C=10/6~10/7, B 여유 2일, 임계 A/C, 목표 차이 -1일을 확인합니다.
2. 승인 이름 ‘검수 기준 1’을 저장합니다. 엑셀 Export 후 수정 없이 재Import하여 변경 0, 데이터 버전 동일을 확인합니다.
3. 엑셀의 업무명·WBS·행 순서를 바꿔 Import합니다. ID가 유지되는지 확인합니다. B 행을 빼도 B가 삭제되지 않아야 합니다. 비고 빈 셀은 보존, `__CLEAR__`는 삭제를 확인합니다.
4. Export한 뒤 앱과 엑셀에서 같은 이름을 다르게 수정합니다. 충돌 기본 미선택, 전후값, 사용자 선택 후 적용을 확인합니다. 잘못된 날짜/중복 ID/없는 선행을 넣으면 셀 진단과 적용 차단을 확인합니다.
5. 작업 O/M/P를 늘려 재계산해도 ‘검수 기준 1’ 날짜는 바뀌지 않아야 합니다. 관계 유형·시차·휴일·추가근무일을 바꾸고 예측을 확인합니다.
6. 모듈 제외로 연결 검토 차단 및 원복을 확인합니다. 고정 날짜 충돌과 재개일 없는 보류도 계산이 차단되어야 합니다.
7. DB 백업 → 이름 변경 → 앱 재시작 → DB 복원으로 이전 입력·기준 일정·이력이 돌아오는지 확인합니다.

## 제한과 이번 범위 밖

SF/음수 시차, 자원 평준화, 상관관계·위험 사건·분포 고도화, 공휴일 자동 취득, 임의 Excel 양식 자동 매핑, 원본 서식/그림 완전 복제, 전체 몬테카를로 배열 저장, EXE 빌드는 구현하지 않았습니다. 기존 Canvas 로드맵은 확률 주변분포와 관계 앵커를 표시하며 자원 기반 실제 시공 간트나 승인 워크플로를 대신하지 않습니다. UI는 기존 레이아웃을 유지한 보완이며 화면 배율·한국어 글꼴·파일 대화상자 및 Windows 수동 클릭 검수는 실제 대상 PC에서 수행해야 합니다.

## 소스 구성과 패키징

`model.py`: UID/정규화/복제 · `storage.py`: SQLite/이전/이력/백업 · `importing.py`: 비교/선택/충돌 · `excel_io.py`: PSL-2 입출력/셀 진단 · `legacy_excel.py`: 기존 Rev1 리더 · `engine.py`: 공통 계산/CPM/몬테카를로 · `app.py`: 기존 Canvas/Tk 화면 · `ui_v2.py`: 추가 워크플로. `python build_release.py`로 소스·예제·문서·검증 기록 ZIP과 SHA-256을 만듭니다. 로컬 DB·가상환경·캐시를 포함하지 않습니다.

기존 화면의 시각 구성 참조: https://github.com/bitovi/jira-auto-scheduler. 해당 프로젝트의 소스·로고를 복제한 포트가 아닌 독립 Python 구현입니다. 의존 패키지의 라이선스는 각 패키지 안내를 따릅니다.
