# 0.2.2 Import 적용 버튼 표시 수정

문제 재현: 기본 Treeview 행 높이와 16행 표, 12행 설명란의 요청 높이가 Import 창을 채워 그 뒤 pack된 최종 적용 버튼이 전혀 표시되지 않았습니다. 실제 Tk에서 1200×800 및 1000×650 창 모두 버튼 winfo_ismapped()=0이었습니다. 파일 선택은 미리보기만 열기 때문에 적용을 마치지 않으면 기존 예제 프로젝트로 시뮬레이션이 실행됩니다.

수정: 창 상단에 변경 사유·확인란·적용/취소 버튼을 고정하고 나머지는 스크롤 가능한 분할 미리보기로 구성합니다. 파일명·가져올 프로젝트·작업 수·아직 적용 전 안내와 선택/오류/경고 수를 표시합니다. 새 프로젝트 파일은 보존되는 별도 프로젝트 미리보기로 바로 열립니다. 적용 후 이전 검색어를 지우고 새 작업목록으로 전환하며 완료 메시지를 표시합니다. 오류 차단, 명시적인 최종 적용, 충돌 검토, 트랜잭션은 유지합니다.

검증 환경: Python 3.12 / Tk 9 / Xvfb. Windows DPI/폰트 수동 검수는 수행하지 않았습니다.

- 전체 49개 테스트 실행 / 49개 통과 / 실패·오류·skip 0. 로그: test_results_0.2.2.txt.
- 새 GUI 회귀: 파일 선택부터 433개 신규 작업 미리보기까지 실제 경로를 실행합니다. 1150×760 / 1000×650 / 680×460에서 적용 버튼 표시와 창 내부 위치를 검증하고 적용 후 검색 초기화·프로젝트/작업목록/상태 전환·새 데이터 시뮬레이션을 검증합니다.
- 취소 시 기존 프로젝트 보존, 오류 시 버튼은 보이되 비활성화됨을 검증합니다.
- 실제 공개 파일 schedules/LNG_CO2_2027_01_Schedule_Import.xlsx로 추가 실행: 14개 예제 → 미리보기 상단 적용 → 433개 작업 / 38개 모듈 / LNG-CC-202701 프로젝트 → 5,000회 계산 성공.
- 실제 파일 결과: 시작/기준일 2027-01-01, P50 2028-04-12 / P80 2028-04-22 / P90 2028-04-28. 이전 예제의 2027년 2~3월 결과와 구별됩니다.
- 입력과 Seed가 같으면 재실행 결과가 같은 것은 정상입니다. 이번 수정 원인은 고정 Seed가 아니라 Import 적용 버튼의 레이아웃 문제입니다.

DB 스키마·의존성·계산 규칙 변경은 없습니다. 기존 DB를 삭제/초기화하지 말고 실행 프로그램 파일만 새 버전으로 교체하세요. 업데이트 전에 기존 프로그램을 종료하고 DB를 백업하세요.
