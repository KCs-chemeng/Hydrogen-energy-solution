# 0.2.1 확률 로드맵 표시 수정 검증

문제: 슬라이더의 선택 분위수는 기존 막대의 범위 끝에만 적용되고 시작/완료 기준점, 작업 연결 실선 및 관계 연결선은 P50에 고정되어 있었습니다. 계산 배열에서는 후행 시작이 선행 완료를 따르고 있었으므로 계산 규칙을 변경하지 않고 표시 기준을 통일했습니다.

수정: 선택 P의 시작/완료 표식·실선·날짜 및 FS/SS/FF 연결선 앵커를 함께 갱신합니다. 시작 P10~선택 완료의 회색 참고 범위와 선택 일정 실선을 구분합니다. 0일 마일스톤은 별도 표식으로 표시합니다. 확률 막대는 여전히 개별 작업의 분위수 요약이며 특정 한 번의 실행 일정이 아닙니다. 고정 실적·착수일 또는 SS 제약으로 원래 일정이 고정된 작업의 시작은 확률에 따라 변하지 않을 수 있습니다.

검증 환경: Python 3.12 / Tk 9 / Xvfb, 기존 의존성 동일.

`DISPLAY=:99 python -m unittest test_core test_v2 test_gui -v`

- 47개 실행 / 47개 통과 / 실패·오류·skip 0. 상세: test_results_0.2.1.txt.
- 새 GUI 회귀: 선행 O/M/P=1/5/20, FS 후행, SS 후행, FF 마일스톤을 5,000회 계산. P75/P95의 시작/완료 표식 좌표를 실제 분위수와 비교.
- FS+0에서 선행 완료 배열과 후행 시작 배열의 모든 반복 값 일치 확인. 선택 확률에서도 두 표식과 연결선 끝점 일치 확인.
- FS/SS/FF 연결선 앵커가 올바른 시작/완료 표식에 연결되는지 확인.
- P95의 FS 후행 시작이 P75보다 뒤로 이동하고 선택 날짜 문구가 갱신되는지 확인.
- 슬라이더 조작이 원 계산 배열을 변경하지 않는지 확인.
- 기존 데이터 안정성·일정 계산·GUI 검증도 모두 통과.

Windows 수동 화면·DPI·폰트·파일 대화상자 검증은 수행하지 않았습니다. 기존 DB 스키마·의존성 변경은 없습니다.
